# khub Full Audit — 2026-07-05

**Status:** report. Five parallel investigations against HEAD `ea00cf2`: an adversarial review of `src/khub/core/`, an adversarial review of `src/khub/cli/` + docs, a black-box CLI stress test (8 phases, 1000-entity corpus), a LinkML/projection architecture audit, and a landscape scan (~100 web searches). Every finding below was reproduced by execution against a throwaway firm-ops workspace; nothing in the repo was modified. Baseline before the audit: 264 tests pass, ruff clean, mypy strict clean — the suite covers the happy paths, and nearly everything below lives outside them.

## Verdict

1. **The concept holds.** No other tool combines an enforced schema that types entities *and* relations, write-time validation, a graph projection, git-native Markdown, and an agent-first read/write surface. The bugs found are seam bugs, not concept flaws.
2. **Stability is one theme, not twenty bugs.** The write and scan paths assume files are in canonical shape, but "Markdown is truth" makes hand-edited files first-class input. Every P0 is a variant of that broken assumption.
3. **LinkML never runs at runtime.** It generates two artifacts nothing consumes. Quarantine it behind an optional extra now; replace it only when a trigger fires.

## 1. Stability

### P0 — corruption or workspace brick

**P0-A. `link`/`unlink` explode a scalar-valued many-relation into characters.**
A many-relation stored as a scalar (`related: alice`) is a state the tool itself blesses: `validate` reports 0 errors on it, and `get`/graph read it as a one-element list. But `link` runs `list(existing)` on the string:

```yaml
# after: khub link acme related bob
related: [a, l, i, c, e, bob]
```

`unlink acme related alice` on the same state prints "Unlinked" and leaves the exploded characters in place. Silent, exit 0. `src/khub/core/entity.py:379` and `entity.py:405-411`.
*Fix:* normalize a string value to `[value]` everywhere a many-relation is read for writing.

**P0-B. One malformed-YAML file bricks the whole workspace.**
`frontmatter.load()` in `index.py:57,62` (`scan_type`) is unguarded. One file with an unclosed bracket — or a tab in the frontmatter — makes every scanning command traceback: `validate`, `check`, `query`, `status`, `stale`, `log`, `reindex`, `viz`, `backfill`, even `get <healthy-entity>`. The command meant to diagnose the bad file is the first thing to die, violating validate's own collect-every-error contract (`integrity.py:8`).

```bash
printf -- '---\ntype: client\nname: [unclosed\n---\n' > clients/broken.md
khub validate   # -> raw yaml.ParserError traceback
```

Same family: a corrupt or missing `.khub/schema.yaml` raises a raw `ScannerError`/`FileNotFoundError` through every command — and the design memo makes hand-editing `schema.yaml` *the* override mechanism, so a typo there is an expected state. The CLI catches only `LocatedError`.
*Fix:* wrap the per-file parse in `scan_type` and surface unparseable files as strays; wrap schema parse/IO failures in `resolve`/`load_schema` as `LocatedError`.

**P0-C. `--field type X` clobbers the type discriminator.**
`create` pins `meta["type"] = type_` (`entity.py:158`) and then the attribute loop (`entity.py:163-165`) overwrites it, because `type` is a declared base attribute. `create(root, "client", {"name": "W", "type": "person"})` writes `type: person` into `clients/` — an instant stray: visible to `query`/`status`, silently excluded by `validate`/`check`/`viz`/`reindex`. The `(type, slug)` identity the graph is keyed on is corrupted at write time, and `--strict` does not help.
*Fix:* pin `type` after the field loop, or pop it in `_partition` the way `draft` is popped.

**P0-D. Over-long `--id` → raw `OSError` traceback.**
A ~300-char slug crashes `add` at `entity.py:174` with `OSError [Errno 63] File name too long`.
*Fix:* cap slug length in `_mint_slug`.

**P0-E. Concurrent `add` on a colliding slug loses writes.**
Slug uniqueness is checked against the index, not atomically with the write. Eight racing `add --id clash` once produced 6 "Created" confirmations and 3 surviving files; an identical rerun lost nothing — nondeterministic. Parallel agents make this path real. Concurrent *edits* to one file stayed clean (last-write-wins, no corruption).
*Fix:* `O_EXCL` create, retry with the next suffix on collision.

### P2 — inconsistencies (batchable)

- **Format black hole.** The meta-schema accepts a per-type `format` (`schema_model.py:57`, default `md`); `entity_path` and `delete` honor it, but `scan_type` globs only `*.md`. A `format: yaml` type is write-only: created, then invisible to every read, and re-`add` under the same name silently overwrites. Dormant in firm-ops. Either glob by `storage.fmt` or reject non-`md` formats at resolve.
- **Docs vs disk.** The design memo's deployment tree puts entities under `knowledge/<type-folders>/`; they actually land at the workspace root (`clients/`, `projects/`, …).
- **JSON `id` split.** `query`/`add`/`get` emit `id` = bare slug; `neighbors`/`impact`/`history`/`stale`/`log`/`validate`/`check` emit `id` = `type/slug`. One key, two contracts.
- **Two stale thresholds.** `khub stale` defaults to 30 days (`gitlog.DEFAULT_DAYS`); `status` and `query --stale` use config `stale_days` = 90. A 60-day-old entity is stale to one and not the other; the memo says they "gate on the same computation".
- **Strays split-brain.** `query`/`status` count strays as entities of their layout type; `validate`/`check`/`stale`/`log`/`backfill`/`viz`/`reindex` exclude them.
- **Read/write parser divergence.** Reads use tolerant python-frontmatter; writes use strict `_split_frontmatter` (`entity.py:505-513`, fence must be line 0). A file with a leading blank line or BOM is readable and visible but un-editable (`malformed_entity`).
- **Slug minting ignores `title`.** `_slug_source` consults only `name`; firm-ops meetings/fragments have no `name`, so default slugs are `fragment`, `fragment-2`, …
- **`reindex` emits broken Markdown links** for filenames with spaces/parens — link text is escaped, the URL is not (`reindex.py:135-137`). Realistic for the HQ-cutover corpus.
- **Table format inconsistency.** `--format table` is silently downgraded to JSON on a non-TTY by every command except `get`, which renders box-drawing into the pipe.
- Smaller, confirmed: self-loops (`link a depends_on a`) accepted and not reported as cycles; `unlink` of a non-existent edge reports success; explicit `--id` collision silently auto-suffixes; `edit <id> updated <value>` is overwritten by the auto-bump (no backdating); duplicate YAML keys silently last-win; `history` defaults to `supersedes`, which firm-ops does not declare; `khub compile` and `init --format` are undocumented; inbound-refusal message is ungrammatical for count 1.
- Latent (confirmed in code, dormant in firm-ops): a type-level override of a *base relation* is honored by the resolved model but dropped from the generated LinkML/Pydantic (`linkml_emit.py:69-72`); overriding only `required` on a base attribute drops the base's `pattern`/`enum` (`resolve.py:109-119`).

### SIMPLIFY — dead surface

`SchemaFile.imports` declared, never read · `determinism.py` `time`-branch unreachable (`time` is not a khub scalar) · `neighbors --both` is inert · `config.yaml` `defaults.format` written by init, read by nothing · `parse_fields`/`_parse_edit` are near-duplicate parsers · `neighbors`/`impact`/`history` CLI each re-wire `build_index(root, load_schema(root))` that a root-taking core entry should hide.

### The unifying fix principle

Every write verb must tolerate any on-disk state the read path accepts (normalize on read), and every scan must degrade per-file, never per-workspace. That one principle closes P0-A, P0-B, P0-C and the parser-divergence P2s as a class.

## 2. Architecture

### LinkML: keep-but-quarantine

Measured, not speculated:

- LinkML runs only inside `compile._generate()`; its imports are function-local. No per-command path loads it (`khub --help` cold start: 0.19–0.21s without it).
- The two generated artifacts have zero runtime consumers. `.khub/generated/models.py` is imported by exactly one test (`tests/test_firm_ops.py:46`); `schema.json` by nothing (the MCP server it targets does not exist yet).
- 100% of live validation is khub's own code over `ResolvedSchema` (`entity._validate_attr`, `integrity.py`). The enforced contract is `schema_model.py` + `resolve.py`, not LinkML.
- Cost is the dependency tail: **77 transitive packages only LinkML needs** (sphinx, rdflib, sparqlwrapper, sqlalchemy, openpyxl, requests, pytest-in-runtime) vs 16 for everything else. ~85% of `khub compile` wall time (~0.53s of 0.63–0.72s) is LinkML; khub's own resolve+emit is 8ms. `determinism.py` exists entirely to babysit the generator's output.
- Feature surface actually used: class/slot/enum generation with `is_a`, `slot_usage`, `multivalued`, `required`, `pattern`, `ifabsent`, `equals_string`. None of LinkML's semantic-web features (URIs, mappings, SHACL/OWL/RDF, SPARQL) are touched.

**Now:** move `linkml`/`linkml-runtime` to `[project.optional-dependencies] compile`. Default install drops from ~100 packages to ~23; `khub compile` prints "install khub[compile]" when the extra is absent. The OKF/LinkML interop story survives intact.

**Replace trigger:** drop LinkML for a ~120-LOC self-emit (JSON Schema directly from `ResolvedSchema`; `pydantic.create_model` if the MCP layer wants typed objects) when either (a) khub ships to third parties and install weight becomes user-visible, or (b) the MCP server lands and khub is emitting its own tool schemas anyway. Until a consumer pulls for it, the rewrite stays parked.

### Projection: networkx stays; search is the gap

Measured on synthetic firm-ops corpora:

| Op | 1000 entities | 5000 entities |
|----|---------------|---------------|
| `build_index` (scan + parse) | 34ms | 178ms |
| `build_graph` (networkx) | 1.7ms | 9.9ms |
| `check` (in-process) | 47ms | 227ms |

End-to-end at 1000 entities, every command ≈ 0.24s wall — all of it interpreter/`uv` startup; graph work is noise. `impact` walked a 60-node `depends_on` chain correctly; `viz` emitted a 775KB self-contained HTML with all 1000 nodes. No O(n²) anywhere.

- **No SQLite node/edge cache** — it would trade "rebuild from Markdown on demand" for cache invalidation to save a sub-200ms scan. Revisit at ~10k entities (scan >300–500ms).
- **Next capability: `khub search` on SQLite FTS5.** Stdlib, zero new dependencies, BM25; the agent's real gap is finding entities by text, not traversing faster. The index is a derived cache, never a source of truth.
- **Vectors:** sqlite-vec (pre-1.0, pure C, rides the same file) as phase 2, only when keyword recall demonstrably misses. LanceDB: no — heavy dependency, separate store, unproven need.
- **kuzu is dead.** Apple acqui-hired Kùzu Inc (agreed 2025-10-09; repo archived 2025-10-10). Strike it from the design memo; if an embedded graph engine is ever needed, oxigraph or the LadybugDB fork.
- **Ergonomic flag:** the fixed ~0.24s startup taxes an agent firing many single-shot commands. Cheap mitigations when it matters: `uv tool install` (planned), batched verbs, or the MCP server as the long-lived surface.

## 3. Landscape and positioning

The empty cell is real: nothing else combines (a) an enforced schema typing both entities and relations, (b) write-time validation, (c) a graph projection, (d) git-native Markdown+frontmatter, (e) an agent-first read/write surface. The near-neighbors each miss exactly one axis:

| Tool | Misses |
|------|--------|
| basic-memory (closest analog) | schema is inferred/advisory; git optional, SQLite indexed |
| Logseq DB | enforced typed relations, but SQLite instead of files |
| Google OKF | the substrate itself; deliberately refuses a content model |
| Zep/Graphiti | typed + bi-temporal facts, but graph DB + LLM-extracted |
| SARA | validate/check/graph verbs over Markdown+git, but requirements-only |
| Notion / Tana / Anytype / Capacities | typed-note UX precedents, all proprietary or non-file stores |

**OKF timing:** announced 2026-06-12 (Google Cloud), v0.1 draft, 6.2k stars, no releases, explicitly credits Karpathy's April-2026 LLM-wiki posts, explicitly stays schema-less ("the interoperability surface, not the content model"). khub adds exactly what OKF refuses to specify — well-timed, and the standard is young enough to track closely.

**Pitch lines that fell out of the research:** *"Google OKF, but the schema is real"* and *"Karpathy's LLM wiki with a compiler."* khub does not compete in the crowded "remember more automatically" agent-memory lane; it competes on structural integrity, git reviewability, and typed queryability.

## 4. Feature recommendations (ranked, value-for-effort)

1. **Type templates on `add`** (Tana supertags, Capacities): write the file pre-filled with the type's required frontmatter, defaults, and empty typed-relation stubs. The schema introspection already exists; this is the single biggest authoring win.
2. **Schema hints to the agent** on `add`/`link`: on failure (or on request), state which attributes and predicates are legal here. Pairs with #1.
3. **Progressive-disclosure JSON**: `query` returns a compact index with stable IDs (~50–100 tokens per hit); bodies hydrate per selected ID. Output-format change; direct token savings for the primary consumer.
4. **CI gate**: `khub check` as a PR action (SARA's model). Thin wrapper over an existing verb; makes "the gate is the schema and git" literal.
5. **Named reciprocal relations**: the schema names the inverse (`reports_to` ⇄ `direct_reports`); inverses are already computed, this makes both directions queryable by name.
6. **FTS5 `khub search`** — the one storage addition (§2).
7. **OKF export parity + an llms.txt-shaped root file**: guarantee "schema-off = valid OKF bundle"; drop an entry file pointing agents at schema + index. Cheapest strategic moat while OKF is hot.
8. Later: typed ingestion (facet path — scaffold typed entities from unstructured sources, then validate); Graphiti-style bi-temporal facts (`valid_from`/`valid_to`, invalidate-not-delete); MCP server with tool behavior annotations and a live `khub://graph` resource; `schema_infer`/`schema_diff` as an authoring aid.

## 5. Verified good

Path traversal is safe (`../../escape`, absolute paths, hostile titles all normalize inside the workspace) · referential integrity hard-fails correctly on write, enums reject wrong case · git degradation is graceful in all three states (no repo / no commits / commits) · round-trip editing preserves comments, key order, and extension keys; edit-same-value, reindex×2, backfill×2 produce zero git churn · workspace resolution finds the nearest `.khub/` from subdirectories and fails cleanly outside one · `.khub/generated/` is deletable without breaking runtime commands · `init` refuses a non-empty target without `--force` and `--force` preserves entities · `remove` refuses while inbound edges resolve and lists them · multi-node cycle detection works · compile output is byte-deterministic across runs.

---

## 6. Recommended order of work

1. **Normalize-on-read + per-file error containment** — closes P0-A/B/C and the parser-divergence class in one pass.
2. **Write-gate patches** — pin `type`; reject comma-lists on single relations; validate dates at write; cap slug length; `O_EXCL` create.
3. **Agent-contract pass** — `--workspace`/`--version`; one `id` format; JSON-always-JSON; one stale threshold; fix `validate <target>` selection.
4. **LinkML → optional extra** — one pyproject change plus an import guard in `compile`.
5. **Features** — templates-on-add → schema hints → FTS5 search.
